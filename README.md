# Личная CRM

Приложение, где я веду контакты людей, которых знаю лично. Подробнее: `specs/01-продуктовая-идея.md`.

## Что нужно установить

- Node.js (LTS) и pnpm
- Docker Desktop: в нём работает база данных

## База данных

База — PostgreSQL в Docker. Настройки подключения лежат в файле `.env`. Его нет в git, потому что там пароль.

**Первый запуск на новом компьютере.** Скопируйте `.env.example` в `.env` и заполните значения.

**Запустить базу** (Docker Desktop должен быть открыт):

```
docker compose up -d
```

**Проверить, что база работает:**

```
docker compose ps
```

В колонке `STATUS` должно быть `healthy`.

**Остановить базу:**

```
docker compose stop
```

Данные при остановке сохраняются. Они хранятся в Docker-томе `personal-crm_db-data`.

## Приложение

Приложение берёт настройки подключения к базе из тех же переменных `POSTGRES_*` в `.env`, что и Docker. Отдельно прописывать подключение не нужно.

**Первый запуск на новом компьютере** (база должна быть запущена):

```
pnpm install
pnpm db:migrate
```

Первая команда ставит библиотеки, вторая создаёт таблицы в базе.

**Запустить приложение:**

```
pnpm dev
```

Затем откройте в браузере http://localhost:3000. Остановить — `Ctrl+C` в терминале.

## Тестовые данные

Чтобы посмотреть приложение на большом списке, можно загрузить 1000 выдуманных контактов с заметками (база должна быть запущена):

```
pnpm db:seed
```

Контакты добавляются к уже существующим, ваши записи не трогаются. Повторный запуск ничего не добавит: скрипт заметит, что тестовые контакты уже загружены. Почты у тестовых контактов — на зарезервированных доменах `example.com`, `example.org`, `example.net`, поэтому совпасть с адресом реального человека не могут.

## Изменения в структуре базы

Таблицы описаны в коде: `src/db/schema.ts`. Если схема поменялась:

```
pnpm db:generate
pnpm db:migrate
```

Первая команда создаёт файл миграции в папке `drizzle/` (его нужно сохранить в git), вторая применяет его к базе. После `git pull` достаточно `pnpm db:migrate`.
